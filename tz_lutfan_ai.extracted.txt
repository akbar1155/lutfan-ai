1. Обзор проекта
1.1. Что мы строим
Lutfan AI — веб-платформа для создания цифровых пригласительных на события узбекской и центральноазиатской культуры. Пользователь заполняет форму (данные события), выбирает вариант дизайна (готовый JPG-шаблон или AI-генерация с нуля), получает готовое приглашение в HD и скачивает его.
Ключевая техническая особенность: весь визуальный рендеринг (фон + размещение текста) выполняется одной моделью Google Gemini 2.5 Flash Image (кодовое имя Nano Banana). Программного наложения текста через canvas — НЕТ. Модель принимает JPG-заготовку или пустой промпт и возвращает финальное изображение с текстом.
1.2. Роли в системе
User — конечный пользователь, авторизуется через Telegram Login Widget, создаёт приглашения.
Admin — управляет контентом (мероприятия, шаблонные тексты, JPG-заготовки, теги стилистики, пользователи).
Роли различаются только полем users.role. Отдельных таблиц или систем нет.

3.3. Асинхронная обработка
AI-генерация занимает 5–40 секунд и НЕ должна блокировать HTTP-запрос.
Схема работы:
Клиент отправляет POST /api/v1/invitations/:id/generate
API валидирует, создаёт задачу в Redis-очереди, возвращает 202 Accepted с job_id
Worker подхватывает задачу, вызывает Nano Banana, сохраняет результат в S3
Worker публикует событие generation:complete в Redis pub/sub
API-сервер, слушающий pub/sub, транслирует событие клиенту через WebSocket/SSE
Клиент показывает результат, обновляет UI
Fallback: клиент дополнительно опрашивает GET /api/v1/invitations/:id/status каждые 3 сек как страховку от разрыва WebSocket.

5. Аутентификация
5.1. Обзор
Единственный способ входа — Telegram Login Widget. Никаких email/password. Причина: единый аккаунт с будущей Telegram Mini App будет синхронизироваться по telegram_id.
5.2. Регистрация Telegram-бота
Через @BotFather создать бота с username lutfan_ai_bot (или согласованным именем)
Через /setdomain привязать домен lutfan.uz
Сохранить bot token в переменную TELEGRAM_BOT_TOKEN
5.3. Флоу авторизации
Пользователь на лендинге нажимает "Войти через Telegram"
Открывается Telegram Login Widget (iframe от Telegram)
Пользователь подтверждает вход, Telegram отправляет POST на callback-URL с параметрами: id, first_name, last_name, username, photo_url, auth_date, hash
Backend валидирует hash по формуле Telegram (HMAC-SHA-256 от отсортированных полей с секретом = SHA-256(bot_token))
Проверяет что auth_date не старше 86400 сек (сутки)
Ищет или создаёт запись в users по telegram_id
Генерирует пару JWT: access (15 мин) + refresh (30 дней)
Access — в Authorization: Bearer header, refresh — в httpOnly Secure SameSite=Strict cookie
Возвращает пользователю его профиль + access token
5.4. Middleware защиты
Все /api/v1/... endpoints кроме /auth/*, /health, /public/* требуют валидного access token.
При истечении access — фронт вызывает POST /auth/refresh с cookie
При истечении refresh — редирект на логин
Endpoints с префиксом /admin/* дополнительно проверяют users.role = admin
Все запросы логируются с request_id для трейсинга
5.5. Логика ban
При каждом запросе middleware проверяет users.is_banned. Если true — 403 Forbidden с описанием причины из ban_reason.

Реализация через Redis. Ключ = user_id (или IP для гостей).

При превышении — 429 Too Many Requests с заголовком Retry-After.

7. Интеграция с Nano Banana (Gemini 2.5 Flash Image)
7.1. SDK и конфигурация
Использовать официальный @google/generative-ai (Node.js) или google-generativeai (Python)
Модель: gemini-2.5-flash-image
API-ключ в переменной GOOGLE_AI_API_KEY
Все вызовы через backend-worker, никогда с фронта
7.2. Путь 1: JPG-шаблон + AI впиcывает текст
Worker получает job из очереди:
Загружает templates.bg_url (JPG-заготовку) в память
Собирает промпт из templates.ai_composition_prompt + текстовых блоков пользователя из invitations.event_data.final_text_blocks
Отправляет multimodal-запрос в Nano Banana: image + text prompt
Модель возвращает изображение с вписанным текстом
Worker сохраняет результат в S3 (bucket: lutfan-public, path: /invitations/{invitation_id}/hd_4_5.jpg)
Публикует событие generation:complete
Пример структуры промпта:
You are given a premium invitation card background. Your task is to place

the following text on the card in an elegant, well-composed manner.



Text blocks (in Uzbek Cyrillic):

- HEADER (elegant script, top center): "Ассалому алайкум!"

- BODY (refined serif, center, may span 2-3 lines): "Азиз меҳмонларимизни севимли қизимиз Азизанинг ақиқа маросимига таклиф этамиз"

- DATE_TIME (bold serif, below body): "20 июн 2026 йил, соат 12:00"

- ADDRESS (smaller serif, below date): "Ресторан Малика, Юнусабад-4, 25"

- FOOTER (elegant script, bottom center): "Хайитбоевлар оиласи"



Composition rules:

- Preserve the entire existing background design

- 200px minimum margin from all edges

- Text must be highly legible against the background

- Use dark text if background is light, light text if background is dark

- Maintain elegant vertical spacing between blocks

- Perfect Uzbek Cyrillic character rendering required (Ҳ, Қ, Ў, Ғ)



Output: single image, same dimensions and quality as input.
7.3. Путь 2: AI генерирует всё с нуля
Worker получает job:
Загружает ai_prompt_presets.base_prompt по ai_preset_id
Собирает mood_tags.prompt_snippet из выбранных пользователем тегов
Формирует финальный промпт: base_prompt + " " + join(mood_snippets, ", ") + текстовые блоки
Отправляет текстовый запрос в Nano Banana (без входного изображения)
Модель генерирует изображение с фоном и текстом
Сохраняет в S3, публикует событие
Пример базового промпта (event: nikoh, стиль: восточная роскошь):
Create a premium wedding invitation card, vertical portrait 4:5 aspect ratio,

high resolution suitable for print (2400x3000 pixels).



Style: {mood_snippets}



Include the following text elegantly composed on the card:

- HEADER: "{header_text}"

- BODY: "{body_text}"

- DATE_TIME: "{date_time_text}"

- ADDRESS: "{address_text}"

- FOOTER: "{footer_text}"



Typography: elegant script for headers and signatures, refined serif for body.

All text centered. Perfect Uzbek Cyrillic character rendering required.

No watermarks. Clean, luxurious composition with generous margins.
7.4. Кэширование
Перед вызовом Nano Banana worker проверяет ai_generation_cache по cache_key:
cache_key = sha256(

  generation_path + "|" +

  (template_id || preset_id) + "|" +

  sorted(mood_tags).join(",") + "|" +

  hash(final_text_blocks) + "|" +

  language + "|" +

  primary_format

)
При попадании — переиспользуется result_url, инкрементируется hit_count. При промахе — генерируется, сохраняется. Кэш живёт вечно, но чистится cron-джобом при hit_count = 1 и старше 60 дней.
7.5. Retry-логика и таймауты
Таймаут одного запроса к Nano Banana: 60 сек
При таймауте — 1 автоматический retry с delay 5 сек
При 429 (rate limit) — exponential backoff (5, 15, 45 сек), максимум 3 попытки
При 500-х ошибках — 2 retry с delay 3 сек
При исчерпании попыток — статус failed, уведомление пользователю с извинением
7.6. Rate limits Nano Banana
На момент написания ТЗ Google AI Studio предоставляет тарифы с разными лимитами. Разработчик обязан:
Уточнить актуальные лимиты в момент разработки
Реализовать очередь с ограничением concurrent requests согласно тарифу
Настроить мониторинг остатка квоты
7.7. Валидация результата
После получения изображения от Nano Banana worker выполняет базовую проверку:
Изображение получено (не пустой ответ)
Формат корректный (JPEG/PNG)
Размер файла > 100KB (защита от «пустых» результатов)
Разрешение соответствует запрошенному формату
Если валидация не прошла — retry (максимум 2 раза), затем failed.

9.1. Buckets

9.2. Структура путей

│   └── {template_id}/preview.jpg

├── mood-tags/

    └── {preset_id}/example.jpg



lutfan-private/

        └── hd_1_1.jpg
9.3. Загрузка файлов
Клиент → Backend (multipart/form-data). Backend валидирует MIME-type, размер (макс 20MB), затем загружает в S3 SDK-методом. Прямой upload с фронта в S3 НЕ используем на MVP (лишняя сложность).
9.4. Скачивание
Публичные файлы — через CDN URL напрямую
Приватные — через backend endpoint GET /api/v1/invitations/:id/download?format=4:5, который проверяет владельца и возвращает signed URL с TTL 1 час
9.5. Cron: удаление истёкших файлов
Ежедневно в 03:00 UTC:
SELECT invitations WHERE expires_at < NOW() AND deleted_at IS NULL
Для каждого — удаление файлов из S3 (все связанные rendered_files)
UPDATE rendered_files SET deleted_at = NOW()
UPDATE invitations SET deleted_at = NOW() (мягкое)
10. Безопасность
10.1. Обязательные меры
HTTPS на всех окружениях (Let's Encrypt / Cloudflare)
HSTS с preload
CORS whitelist (только lutfan.uz и поддомены)
CSP-заголовки (запрет inline scripts, whitelist origins)
X-Frame-Options: DENY (кроме страниц с Telegram Login Widget)
X-Content-Type-Options: nosniff
Rate limiting через Redis
Валидация всех входных данных на бэке (не доверять фронту)
Санитизация текстов пользователя перед подстановкой в промпт (защита от prompt injection)
Prepared statements везде (защита от SQL injection). Через ORM это обеспечено автоматически
Хэширование refresh token в БД (никогда не хранить в plain text)
Секреты — только в env-переменных, никогда в коде
10.2. Защита от prompt injection
Пользовательские тексты попадают в промпт для Nano Banana. Возможна попытка "перепрограммировать" модель.
Меры защиты:
Обрезка длины полей до maxLength из fields_schema
Экранирование фигурных скобок и системных ключевых слов
Обёртка текста пользователя в кавычки внутри промпта
Разделение system prompt и user data чётким разделителем
Валидация результата (не отдаём, если модель отклонилась от задачи)
10.3. Валидация Telegram Login Widget
Обязательная последовательность:
Извлечь все параметры кроме hash, отсортировать по ключу, склеить key=value через \n
secret_key = SHA-256(bot_token)
computed_hash = HMAC-SHA-256(sorted_string, secret_key)
Сравнить с полученным hash — не равны, отказ 401
Проверить auth_date > NOW() - 86400 — иначе отказ 401
10.4. Приватность
Публичная страница /privacy-policy на 3 языках
Публичная страница /terms на 3 языках
При регистрации — чекбокс "Согласен с условиями"
Возможность удаления аккаунта (GDPR-like): удаляет users + связанные записи через CASCADE
